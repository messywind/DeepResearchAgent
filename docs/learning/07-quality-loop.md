# 07｜草稿精修、评估与 Red Team

## 三层质量加工

1. `draft_agent.py` 先生成研究简报和报告初稿。
2. 外部研究完成后，`refine_draft_report` 用研究笔记修订草稿，并由 Evaluator 评分。
3. Red Team 主动寻找逻辑漏洞、事实缺失和证据不足，把批评意见送回 Supervisor；满足质量条件或达到上限后，Writer 生成最终报告。

## 为什么不是一次性生成

一次 LLM 调用很难同时完成问题拆解、证据搜集、事实核验、结构组织和自我批评。把质量闭环拆成“生成 → 评估 → 反驳 → 修复”，可以提高可解释性，也能为每一步设置上限和指标。

## 需要关注的状态

- `quality_history`：观察多轮评分是否真正提升。
- `active_critiques`：观察批评是否被消费，而不是无限累积。
- `needs_quality_repair`：观察路由是否在所有分支都有明确默认值。

## 面试表达

Evaluator 提供量化信号，Red Team 提供对抗性信号；两者共同把“模型觉得写完了”变成“系统有证据地判断是否足够好”。
